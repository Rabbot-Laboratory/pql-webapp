## Part 2. 技術的知見(ここが今回の本体)

### 2.1 遅い歩容ほど悪い ← 直感と真逆・最重要

同一のクロール形状を3つの周期で比較(記録 `20260830_091959_freeplay4`):

| 周期 | 軸の実移動量 | 前右股の端張り付き | 操作者評価 |
|---|---|---|---|
| 20秒 | 4,833 u/s | **41.9%** | 効果なし |
| 12秒 | 7,714 u/s | 19.6% | あまり歩かず |
| **8秒** | **10,190 u/s** | **0.0%** | 比較的歩いた |

**理由**: バルブに不感帯があり、**軸は追従誤差が十分育つまで動かない**。
指令が速いほど誤差が育ってバルブが開き、かつ指令の反転が早いので機械端へ
押し付けられない。

**帰結**: MuJoCoシミュレーションは「追従するアクチュエータ」を前提とするため
逆の予測をする。**シミュのランキングを信用しないこと**。転倒判定にのみ使う。

### 2.2 「動きの量」は歩行性能を予測しない

全12走行区間の横断分析(記録 freeplay〜freeplay5):

| 歩容 | 周期 | 移動量 | **Rollコヒーレンス** | 後足接地率 | 操作者評価 |
|---|---|---|---|---|---|
| **walk_trot_fast8** | 8s | 8,081(最小) | **0.80** | **26.7%** | **安定** |
| walk_crawl_fast8 | 8s | 10,344 | 0.45 | 18.9% | 比較的歩いた |
| walk_crawl_fast4 | 4s | 13,696 | 0.31 | 4.9% | — |
| walk_crawl | 20s | 11,172 | 0.15 | 0.1% | 40cm(別条件) |

**コヒーレンス** = 姿勢の揺れが歩行周期にどれだけ同期しているか。
本物の体重移動は周期ごとに繰り返すが、ただの振動は繰り返さない。
**トロット位相だけが規則正しい体重移動を生んでいる**。

### 2.3 ファームに「答え」が書いてあるのに使われていない

`pql-firmware`(現行、ESP32×2)の `main.ino`:

```cpp
// 実測されたバルブの開き始め角のテーブル(定義されているが未使用)
float valveOffsetStartAngle[4] = {49, 27, 74, 46};    // 縮みはじめ
float valveStrokeStartAngle[4] = {94, 142, 168, 140}; // 伸びはじめ
...
// 制御則はテーブルを一切参照せず、PID出力をそのままサーボ角に加算
float angle = vCommand[i].calcCommand(target, current) + valveCenterAngle[i];
valve[i].write(constrain(angle, 0, 180));
// しかも出力は ±50° にクリップ
vCommand[i].clipLimitEnable(true, 50, -50);
```

テーブル通りなら、伸び開始142°/168°の軸は**PID経由では永久に開かない**
(クリップ上限140°)。「±300単位では動かない」「片方向だけ死ぬ」の正体。

**推奨パッチ**(20行程度、PIDはそのまま活かせる):

```
|u| < ε      → angle = center            (閉じて保持)
u > 0(伸び) → angle = strokeStart[i] + k*u   (閉領域を飛び越える)
u < 0(縮み) → angle = offsetStart[i] - k*|u|
```
併せて: 積分クランプの有効化、クリップの軸別化、圧力送信の有効化
(現在 `sendDataPVC` で 0 固定にコメントアウトされている)。

### 2.4 位置センサに大きなスパイクノイズがある

| 状態 | 1ティック(40ms)あたりの位置ジャンプ 中央値/p95/最大 |
|---|---|
| **静止中** | 2〜14 / 49〜319 / **937** |
| 歩行中 | 5〜32 / 77〜404 / **2902** |

シリンダの物理限界は40msで約33単位。→ **電気ノイズ**。これがESP32のPIDに
入り、歩行中はバルブが時間の46〜59%も全開で暴れていた。

対処済み: サーバー側 `PositionSpikeFilter`
(`src/highend_server/application/position_filter.py`)。物理的にありえない
速度のジャンプを棄却。**ただしESP32内部のPIDは保護できない**(ファーム側が必要)。

### 2.5 実行される振幅は指令の1.5〜4.5倍

| 軸 | 指令振幅 | 実測振幅 | 倍率 |
|---|---|---|---|
| FR膝 | ±398 | ±1806 | **4.5** |
| FR股 | ±1100 | ±1836 | 1.7 |

膝の指令が小さすぎ(4〜5°)、実際はノイズと過走に支配されて暴れていた。
「膝を活かせていない」という観察の実体。

### 2.6 3Dプレビューの符号が全関節で反転していた(修正済み)

target増加時の実機の曲がり方向が3D表示と逆だった。`joint_preview` の符号
(股−1/膝+1 → 股+1/膝−1)と `ACTUATOR_HEIGHT_EFFECTS` 全8軸を反転(76f667e)。

**重大な副作用**: この符号は `model_derived_mixing_matrix()` 経由で
姿勢安定化・適応歩行・立位保持の補正方向を決めている。つまり
**これまでの姿勢補正はすべて逆向きだった可能性が高い**。
反転後の実機検証(手動傾斜テスト)は**未実施**。適応モードを使う前に必須。
