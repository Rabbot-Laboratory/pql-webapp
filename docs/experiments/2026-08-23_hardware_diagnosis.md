## 結論(重要度順)

1. **軸0(右前股)はハード故障だった → セッション中に物理調整で復活。**
   朝の時点では位置4095固着・バルブ指令フルでも5往復×3秒間ゼロ移動。
   8/11の歩行ログでも同じ張り付きがあり、**8/11の歩行試験は実質7軸で走っていた**。
   復活後は動くが現ゲイン(190/90)で発振気味(振れ幅~2900)。要ゲイン調整。

2. **エア供給が支配的な変数。** セッション中に2回「タンク圧が徐々に抜けて挙動が
   劣化→無反応」を経験。エア切れ時の症状は「小誤差方向だけ死ぬ」「時間とともに
   悪化」「浮かせた脚が重力で落ちる」で、軸故障と誤診しやすい。
   **以後の全実験はコンプレッサー稼働・ゲージ確認とセットで行うこと**
   (供給圧センサ1個の追加が根本対策 — 数百円)。

3. **小誤差(±300)ではバルブ不感帯を超えられない軸が多い。**
   誤差±300 → ESP32のPID指令が中立±100〜200程度 → バルブ開かず不動。
   誤差4095(フルストローク)なら全軸動く。立位保持は小誤差修正の連続なので、
   これが「立てない」のソフト側の主因。対策候補: ゲイン再調整(P上限255の8bit制約
   あり)、I項の活用、またはESP32ファームウェアでの不感帯補償。

4. **軸ごとの最大速度差が2.6倍**(フルストローク時の実測、エア十分時):

   | 軸 | 速度 u/s | 動き出し遅れ |
   |---|---|---|
   | 1 右前膝 | ~1200 | 0.14-0.20s |
   | 3 左前膝 | ~880 | 0.14s |
   | 7 左後膝 | ~740 | 0.14-0.40s |
   | 2 左前股 | ~660 | 0.20-0.27s |
   | 6 左後股 | ~575 | 0.20-0.28s |
   | 4 右後股 | ~525 | 0.20-0.30s |
   | 5 右後膝 | ~470 | 0.14-0.33s |
   | 0 右前股 | (故障中のため未計測) | - |

   歩容CSVの軸別先行(phase_advance)は本来この速度差で決めるべき。

5. **ゲインは軸別に最適値が違う。** エア復旧後のP250/I60一律比較では:
   軸6(左後股)は大幅改善(t63 0.2s・静か)、軸5(右後膝)は伸びが復活、
   一方で高I(160-200)が入っていた軸1/3は発振悪化。一律変更はダメで、
   軸別グリッド探索(`scripts/probes/gain_grid.py`)を**エア安定時に**やり直すのが次の一手。
